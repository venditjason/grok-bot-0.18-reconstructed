# 벤디트봇 iPhone 상세 개발지시서

기준일: 2026-10-12. 대상 저장소: `venditjason/grok-bot-0.18-reconstructed`.
구현 위치: `apps/ios`. 관련 서버: `venditjason/vendit-rabbit`.

## 목표와 완료의 정의

본인 iPhone에서 에이전트·팀에 지시하고, Mac mini 또는 Rabbit에서 실제 작업을 수행하며, 진행·결과·승인 요청을 확인하는 개인용 Companion을 완성한다. Mac mini 한 대에 연결된 여러 프로젝트를 지원한다. iPhone에서 CLI 계정을 복제하거나 개발 프로세스를 직접 실행하지 않는다.

실제 기기에 설치한 앱에서 지시를 한 번 접수하고, 정확한 프로젝트의 실행기가 실행해 결과물과 PR을 만든 뒤, 폰에서 최종 상태를 확인해야 제품 완료다. 시뮬레이터 화면, HTTP 202, 모의 응답, 소스 생성만으로 완료라 표시하지 않는다.

## 이미 있는 코드와 검증 한계

- SwiftUI 앱, Rabbit 고정 GET 작업 조회, HTTPS·프로젝트·작업 식별자 검사, 리디렉션 차단, 응답 크기 제한.
- 프로젝트별 키체인 보관 및 설정 취소 시 기존 값 유지.
- 에이전트·팀 지시 초안과 공유 시트. 현재 원격 전송은 구현되지 않았다.
- 기존 독립 Swift 계약 검사 17개 통과. macOS SDK 정적 검사는 iOS 빌드와 다르다.
- 2026-10-12 준비 기록상 정식 Xcode/iOS SDK, 시뮬레이터 빌드, 실제 기기 서명·설치, 실제 Keychain 통합 검증은 미완료다. 착수 시 환경을 새로 확인한다.
- 현재 메모리 초안은 종료 시 사라진다. 제품에서는 이를 반드시 영구 보관으로 교체한다.

## 우선순위와 사용자 흐름

필수 출시는 I01~I08의 개인 기기 연결·지시·결과 확인과 I09의 전경/복귀 안정성·접근성까지다. APNs 푸시, 추가 기기 배포, 오프라인 결과 전문 동기화, 위젯은 후속 선택 기능이다.

첫 실행 → 서버·프로젝트 연결 → 권한과 Host 준비 확인 → 에이전트/팀 선택 → 지시·첨부 작성 → 영구 접수 → 실제 실행 추적 → 결과/PR/승인 확인으로 이어진다. 접수 실패 화면에서는 초안을 유지하고, 연결 설정을 바꿔도 원래 요청의 프로젝트와 UUID는 바꾸지 않는다.

## 작업 순서와 레인 소유권

각 단계는 작은 PR로 진행하고, 명시된 검증을 통과한 변경만 병합한다. 하나의 파일은 한 레인이 소유하며 공통 계약 변경은 먼저 합의한다.

사용자가 지정한 개발 레인 모델은 Astra, 추론 강도는 extra high다. 실제 공급자 카탈로그의 해당 모델 ID와 effort를 확인해 배정하고, 미제공이면 대체 사실을 숨기지 않는다. 실행 슬롯은 우선 최대 4개로 두며 서버/Host 한도에 맞춰 조정한다. 루틴 감시용 저비용 모델 정책과 개발 레인 배정은 구분한다.

1. **계약·서버 레인:** Rabbit 실제 API/권한 조사, 모바일 세션·대상 조회·지시·상태 계약, OpenAPI와 계약 테스트. 소유: Rabbit 서버와 공통 계약.
2. **iOS 코어 레인:** 네트워크·Keychain·로컬 데이터·멱등 전송·재연결. 소유: `Sources/CompanionCore`, 저장소와 네트워크 테스트.
3. **iOS 화면 레인:** 대상 목록·채팅·첨부·설정·상태·접근성. 소유: `App` 화면. 코어 계약 확정 후 통합.
4. **실행·통합 레인:** Mac mini 다중 프로젝트 라우팅, Rabbit 실제 실행, 승인·PR 결과 추적. 운영 SQL/권한 변경은 검토한 구체 범위를 적용한다.
5. **독립 QA 레인:** 계약·기기·재시작·장애·접근성·데이터 보존 검증. 작성자가 자신의 성공 메시지만 검증 결과로 채택하지 않는다.

먼저 1~3단계를 병렬 수행하고, 실제 실행 준비가 된 뒤 4~5단계를 통합한다. 서버가 실행 불가하면 iOS 작업은 계속하되 실제 실행 완료를 주장하지 않는다.

## I01 — 설치와 빌드 기반

- Swift 6 지원 Xcode, iOS SDK, 지원 최소 iOS 버전과 기기 모델을 확인해 저장소에 고정한다.
- 현재 Xcode 프로젝트와 Swift Package를 유지하고 외부 패키지는 필요·라이선스·버전을 명시한다.
- 시뮬레이터 Debug/Release 빌드와 XCTest 실행을 CI에서 재현한다. 인증 정보 없는 검사와 서명 작업을 분리한다.
- 우선 본인 iPhone에 Xcode Personal Team으로 직접 설치한다. App Store 공개 출시는 필요 없다. 무료 서명의 재설치 주기를 설치 화면에 설명하고 실제 프로파일 만료일을 확인한다.
- 유료 가입·결제·TestFlight·Ad Hoc 전환은 자동 신청하지 않는다. 기존 Apple 계정의 인증은 사용자가 직접 완료한다.
- 완료: 시뮬레이터 실행 증거, 실제 기기 설치·실행 증거, 빌드 버전·커밋·서명 만료 기록.

## I02 — 인증과 다중 프로젝트 연결

- 프로젝트 키는 기존 API가 허용하는 작업만 수행한다. 프로젝트 키로 소유자·관리자 권한을 흉내 내지 않는다.
- 개인용 첫 경로는 프로젝트 연결 정보와 프로젝트 API 키의 안전한 등록이다. 원하면 Mac에서 명시적으로 생성한 일회성 페어링 코드로 등록 입력을 줄인다.
- 팀·에이전트 동기화 등 소유자 기능은 서버가 검증하는 별도의 기기 세션을 설계한다. 짧은 액세스 토큰, 갱신 회전, 기기별 철회, 서버 측 사용자·조직·프로젝트·대상 검사와 감사를 적용한다.
- macOS/Claude/Codex의 로그인 파일·개인 키를 폰이나 QR에 복사하지 않는다. QR에는 단기 일회성 교환 정보만 넣는다.
- 서버 origin+프로젝트+기기별로 인증을 격리한다. Keychain에만 비밀을 저장하며 로그·URL·알림·클립보드 자동 복사에 포함하지 않는다.
- 프로젝트를 여러 개 저장하고 최근 선택을 복원한다. 연결을 바꿔도 다른 프로젝트의 초안·기록·키를 삭제하지 않는다.
- 완료: 서로 다른 두 프로젝트와 두 사용자로 교차 접근 거부, 철회·만료·서버 교체·중복 페어링 검증.

| 기능 | 현재 경로/계약 | 구현 시 요구사항 |

| 에이전트/팀·대화 | 모바일 공개 계약 미확정 | 소유자 인증·기기 권한을 포함한 서버 계약부터 구현 |
| 파일 업로드 | 모바일 공개 계약 미확정 | 프로젝트/요청에 묶은 private 업로드, 크기·해시·만료·접근 검사 |

새 엔드포인트와 저장 구조는 서버 레인이 기존 구현을 조사한 후 고정한다. 미구현 계약을 이미 제공되는 API로 취급하지 않는다.

## I03 — 실제 지시 접수와 중복 방지

- 기존 `POST /v1/projects/{projectId}/runs`의 objective/workflow_template/acceptance_criteria/constraints 계약을 재사용한다. 필드·최대값은 서버 소스를 기준으로 공유 계약에서 검증한다.
- 사용자가 입력을 누르기 전에 초안과 요청 UUID를 로컬 영구 저장한다. 같은 요청 재시도는 동일 Idempotency-Key와 정확히 같은 본문을 사용한다.
- 202는 접수다. run_id와 프로젝트를 검증한 뒤 고정된 신뢰 origin의 상태 경로로 조회한다. 서버의 임의 poll URL/Location을 따라가지 않는다.
- 타임아웃·연결 단절·5xx는 접수 여부 불명으로 처리하고 새 UUID로 자동 재전송하지 않는다. 서버 상태 확인 또는 동일 요청의 멱등 재시도로만 복구한다.
- 재전송 직전 목표를 수정하면 새 요청으로 분리하고 이전 불명 요청을 숨기지 않는다. 앱 종료·재시작 후에도 요청 UUID와 상태가 유지돼야 한다.
- 실제 작업이 시작되기 전 명백한 미접수만 대체 실행기로 전환한다. 원격 접수 후 로컬 실행을 겹쳐 시작하지 않는다.
- 완료: 네트워크가 각 단계에서 끊겨도 하나의 사용자 요청이 한 번만 실행되는 실제 계약 시험.

## I04 — 에이전트·팀·대화

- 홈에서 이름·사진이 있는 에이전트와 팀을 표시한다. 팀은 대표 이름과 작은 멤버 사진을 표시한다.
- 한 에이전트의 여러 팀 소속을 지원하고 임의 8명 제한을 추가하지 않는다. 서버 정책·현실적인 페이지네이션과 렌더링 제한은 유지한다.
- 선택 즉시 해당 대화와 입력창을 연다. 응답에 실제 에이전트 이름을 표시하고 사용자 메시지에 불필요한 '나' 헤더를 붙이지 않는다.
- 짧은 입력은 한 줄에서 시작해 확장한다. 오른쪽 '입력' 버튼, 키보드 회피, 안전 영역, 한글 조합, 복사·텍스트 선택을 지원한다.
- 팀 지시는 대표에게 전달하고 위임 대상·진행·결과를 표시한다. 활동 중인 팀의 추가 지시는 이미 시작한 턴을 변조하지 않고 이후 턴의 문맥에 반영한다.
- 재접속 시 이벤트 ID/커서로 중복 표시를 제거한다. 이력이 삭제·만료됐으면 빠진 내용을 명확히 알리고 무한 재연결하지 않는다.
- 완료: 팀 2개에 공유 멤버 1명, 별도 에이전트 2명, 긴 대화·빈 대화·삭제된 대상·실행 중 대상 전환 시험.

## I05 — 영구 초안과 데이터 보존

- SwiftData/SQLite 등 버전이 있는 로컬 저장소로 대상별 초안, 요청 접수증, 최근 상태, 첨부 메타데이터를 보관한다.
- 저장 실패 시 사용자가 입력한 내용을 지우지 않는다. 성공적인 접수 확인 후 전송한 버전의 초안만 지우며 그동안 추가한 문장은 유지한다.
- 마이그레이션 전 백업과 실패 시 복구 경로를 제공한다. 손상된 레코드는 원문을 격리 보존하고 전체 저장소를 초기화하지 않는다.
- 로그아웃·연결 해제·대상 삭제의 영향을 구분한다. 이 기기 인증 제거와 원격 계정 권한 철회는 서로 다르다.
- 완료: 작성 중 강제 종료, 앱 업데이트, 저용량, 동시 상태 수신, 저장소 구버전·손상 입력에서 초안과 작업 보존.

## I06 — 첨부

- '+'에서 파일/사진 선택, iPad 드래그 앤 드롭, 공유 시트로 받은 파일을 명시적으로 처리한다. 전체 사진 라이브러리 권한을 요구하지 않는 선택기를 우선한다.
- 선택된 파일만 private staging에 복사하고 MIME·크기·확장자·개수와 해시를 검증한다. 보안 범위 URL 권한은 읽는 동안만 유지한다.
- 이미지와 UTF-8 문서부터 시작하고 PDF/Office는 실제 추출기 또는 공급자 지원이 검증된 후 활성화한다. 미지원 형식을 성공한 첨부로 표시하지 않는다.
- 모델·실행기별 전달 계약을 유지하고 모델에 전달되지 않은 첨부를 분석했다고 표시하지 않는다. 전송 전 파일명·크기·제거 버튼을 제공한다.
- 민감 파일을 자동 수집하지 않으며 저장소 비밀·키·로그 전체를 개선 요청에 자동 첨부하지 않는다.
- 완료: 손상 이미지, MIME 위장, 큰 파일, 읽기 권한 취소, 중간 종료, 다른 프로젝트 첨부 혼입 거부.

## I07 — Mac mini/Rabbit 라우팅

- 폰은 명령·조회 클라이언트다. Mac mini/Rabbit이 실행한다. 프로젝트마다 실행기, 저장소, 작업 루트와 정책을 저장한다.
- 동일 Mac mini에 두 개 이상 프로젝트를 매핑하고 작업 폴더·Git worktree·환경·동시성·결과 경로를 분리한다.
- 대표/PM의 연결된 Codex·Claude와 실제 개발 Rabbit 레인을 구분한다. 자동 모드에서 팀에 지정한 Rabbit 프로젝트가 개발 실행 우선이다.
- Host offline, 모델 로그인 만료, 사용 한도, DB 준비 미완료, 승인 대기를 구별해서 보여준다. 실행기가 준비되지 않은 상태를 정상 대기처럼 숨기지 않는다.
- 루틴 감시는 불필요한 모델 호출 없이 수행하고, 필요한 문서 요약·분류에만 설정된 저비용 모델/effort를 사용한다. 공급자 실제 카탈로그에 없는 모델 이름을 발명하지 않는다.
- 완료: 한 Mac에서 두 프로젝트 동시 실행, 한 프로젝트 실패 시 다른 프로젝트 지속, Host 재시작·네트워크 복구 후 중복 작업 없음.

## I08 — 승인·결과·리포트

- 저장소 삭제, 파괴적 변경, 비밀 공개, 접근권 확장 등 기존 금지·승인 정책을 서버에서 강제한다. 모바일 화면에서 숨기는 것만으로 정책을 구현하지 않는다.
- 승인 요청은 작업 ID·대상·변경 요약·만료·1회성 토큰에 묶는다. 다른 계정 승인, 오래된 승인, 중복 제출을 거부한다.
- 프로젝트 키가 원격 취소를 허용하지 않으면 취소 버튼을 제공하지 않는다. 로컬 대기 취소와 원격 작업 취소를 구분한다.
- 완료 결과에는 검증된 상태, 산출물, 테스트 결과, PR 링크, 병합 커밋을 표시한다. 모델이 문장으로 '병합 완료'라고 말한 것은 증거가 아니다.
- 버그/개선 요청은 '리포트' 에이전트와 동일한 영구 요청 계약으로 접수하고 단계별 상태를 공유한다. 테스트를 통과하고 현재 head가 검증된 PR만 정책에 따라 자동 병합한다.

## I09 — 백그라운드·알림·접근성

- iOS 백그라운드에서 무제한 폴링할 수 있다고 가정하지 않는다. 전경 시 제한된 폴링/이벤트 스트림, 배경 시 중단, 복귀 시 커서 복구를 구현한다.
- Push는 실제 APNs·서버 토큰 등록과 철회가 준비된 경우에만 제공한다. 미구현이면 알림이 온다고 안내하지 않는다.
- 잠금 화면에는 비밀·업무 본문을 기본 표시하지 않는다. 상태 중심 알림과 앱 내 상세로 분리한다.
- 작은 iPhone, 큰 글자, VoiceOver, Reduce Motion, 다크 모드, 키보드와 회전에서 잘림·겹침을 확인한다.
- 상태는 색뿐 아니라 텍스트로 표시한다. 버튼 터치 영역, 오류 안내, 재시도와 초안 유지가 접근 가능해야 한다.

## 필수 검증과 납품

1. Swift 계약/스토리지/멱등/권한 테스트, 서버 계약 테스트, 타입·빌드 검사.
2. 시뮬레이터 UI: 새 연결, 대상 전환, 입력, 첨부, 조회, 단절·재연결, 설정 취소.
3. 실제 iPhone: Keychain 잠금/해제, 강제 종료, 업데이트 후 데이터 보존, 한글 입력, 파일 선택, 실제 HTTPS.
4. 실제 통합: iPhone 1회 접수 → 선택된 Mac/Rabbit → AI 호출 → 테스트 → 산출물 → PR → 정책에 따른 병합 → iPhone 상태 반영.
5. 부정 시험: 교차 프로젝트/사용자, 리디렉션, 악성 응답, 만료·철회 키, 잘못된 이벤트 커서, 접수 불명, 중복 버튼, 파일 변조.
6. 스트레스: 다중 프로젝트/팀 동시 조회, 긴 대화, 빠른 대상 전환, 연결 flapping. 부하 데이터는 별도 QA 환경에 한정하고 운영 계정 한도를 소모하는 반복 AI 호출은 하지 않는다.

각 PR은 변경 이유·계약·테스트·남은 제약을 설명한다. 최종 산출물은 소스/PR/커밋, 실제 빌드와 설치 경로, 테스트 원문·스크린샷, 데이터 보존 결과, 사용자 설치 안내, 미완료 항목이다. 테스트 생략·빌드 불가·실기기 미확인은 별도 항목으로 남긴다. 실제 기기 설치나 원격 실행 증거 없이 '100% 완료'로 닫지 않는다.

## 단계별 완료 보고 형식

각 레인은 `단계 ID / 대상 커밋 / 변경 파일 / 실행한 명령 / 통과·실패·제외 수 / 실제 호출 여부 / 증거 위치 / 남은 의존성`을 리포트에 남긴다. 단위·모의·스테이징·운영·실기기 검증을 구별한다. 최종 대표는 서로 다른 프로젝트의 동시 실행과 실제 iPhone 왕복 1건을 독립 재확인한 뒤 종료한다.

App Store 공개 없이 본인 기기에 설치할 수 있으며, 무료 Personal Team은 7일 후 재빌드·재설치가 필요하다. 공식 근거: [Apple Developer account overview](https://developer.apple.com/help/account/basics/about-your-developer-account), 2026-10-12 확인. 유료 가입 없이 진행 가능한 범위를 먼저 구현한다.

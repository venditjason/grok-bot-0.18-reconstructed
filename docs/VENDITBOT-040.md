# 벤디트봇 0.4.0 개발·검증 기준

## 사용자 동작

- 사이드바의 **루틴**에서 에이전트 또는 팀을 대상으로 반복 작업을 등록·수정·삭제하고 켜거나 끈다. 에이전트·팀 대화에서도 해당 대상의 루틴으로 바로 이동한다.
- 루틴은 일정 간격 또는 지정 시간대의 요일·시각으로 설정한다. 실제 실행은 대상의 현재 연결 우선순위, 모델·effort 정책, Rabbit 프로젝트 설정을 따른다.
- 에이전트는 `list_routines`, `create_routine`, `update_routine`, `set_routine_enabled`, `delete_routine`을 사용할 수 있다. 본인과 현재 대표로 있는 팀만 관리한다. 명시적인 사용자 변경 요청이 없는 경우 승인 창을 거친다. 앱의 차단 규칙은 항상 우선한다.
- 응답의 **벤디트봇** 옆에 **작업 정책** 태그를 표시한다. 같은 행 오른쪽의 연결 태그는 실제 시도 횟수·결과를 보여준다. 태그를 누르면 해당 응답에 기록한 정책과 연결별 오류를 확인한다.
- 사이드바 상단 **앱 연결**에서 Gmail, Google Calendar, Google Drive, Google Docs, Google Sheets, Notion, Slack, GitHub를 관리한다. AI 모델 로그인과 별개의 인증이다.

## 예약 실행과 보존

앱이 실행 중일 때 약 15초 간격으로 예약을 확인한다. Mac 잠자기 또는 앱 종료 중 놓친 실행은 한 번으로 합치며 과거 일정을 몰아서 반복하지 않는다. 같은 에이전트 및 겹치는 팀원의 진행 중 작업과 충돌하지 않도록 기존 실행 큐를 사용한다. 앱을 종료한 상태에서 macOS를 깨우는 기능은 포함하지 않는다.

`routines.json`에 실행 예약을 먼저 영구 저장하고, 대화 또는 팀 실행에 상관관계 ID를 기록한 다음 제공자 실행 큐에 넣는다. 재시작 후 완료 여부가 불분명한 실행은 자동으로 반복하지 않고 해당 루틴을 비활성화한다. 사용자가 결과를 확인한 후 향후 일정만 다시 활성화한다. 루틴을 끄는 동작은 이미 시작한 작업을 취소하지 않는다. 진행 중이거나 결과가 불분명한 실행이 있는 동안에는 삭제할 수 없다.

초안은 창 이동·재시작에도 보관한다. 생성 요청 ID로 중복 등록을 막고 수정·삭제는 저장 버전을 대조한다. 충돌이나 파일 손상이 있으면 원본을 덮어쓰지 않는다. 업데이트 준비·종료 동안 새 예약을 시작하지 않고, 업데이트 또는 종료를 취소하면 예약 감시를 재개한다.

## 앱 연결 범위

초기 커넥터는 **조회 도구**를 제공한다. 이메일 전송, Slack 게시, 외부 문서 수정, GitHub 변경·PR 생성은 이 커넥터에 포함하지 않는다. 개발 작업의 PR 작성은 별도로 연결한 Rabbit 경로를 사용한다.

Google은 등록한 Desktop OAuth 클라이언트와 활성화된 Workspace API가 필요하다. Notion은 공식 MCP 서버에 동적으로 앱을 등록한다. Slack은 PKCE를 켠 전용 앱과 고정 localhost 콜백 설정이 필요하다. GitHub는 선택한 저장소에 설치한 전용 GitHub App을 권장하며 Contents·Issues·Pull requests·Metadata 읽기 권한으로 설정한다. OAuth App 방식은 프로필·공개 저장소 범위임을 구분해 표시한다.

각 OAuth 권한은 공식 제공자의 브라우저 화면에서 사용자가 확인한다. 인증 값은 macOS 보안 저장소로 암호화하며 화면·초안·내보내기·모델 도구에 전달하지 않는다. 앱별 토큰과 등록 설정은 기존 Claude/Codex/Rabbit 인증과 별도 키로 저장한다. 연결 해제는 로컬 인증을 제거하며 제공자 측 권한 철회와 구분한다.

`list_connected_apps`와 `read_connected_app`은 연결된 앱의 허용된 조회만 노출한다. 한 응답 도중 다른 계정으로 재연결하면 이전 응답의 권한으로 새 계정을 읽지 못한다. 실제 자료 조회에는 기존 민감 정보 전달 규칙을 적용한다. 외부 자료는 출처 데이터로 취급하며 지시문으로 신뢰하지 않는다.

## 검증과 완료 조건

1. 자동 검사에서 예약 중복·재시작·시간대/DST·수정 충돌·삭제·팀 권한 변경·차단 규칙을 확인한다.
2. OAuth state/PKCE, 허용 서버, 콜백·시간 제한, 토큰 교체, 계정 재연결, 취소·종료, 출력의 인증 값 제거를 검사한다.
3. 실제 브라우저에서 등록·수정·활성 전환·삭제, 정책 및 연결 모달, 여덟 앱 목록과 등록 화면을 조작한다. 합성 화면 검증과 실제 계정 테스트를 구분한다.
4. Google 검사는 실제 API 읽기 응답을 요구한다. Docs/Sheets는 조회 가능한 문서 ID가 필요하다. MCP 초기 연결 및 도구 목록 확인은 실제 문서·채널·저장소 읽기 성공으로 표시하지 않는다.
5. 공식 공개 인증 서버 탐색, 합성 OAuth 테스트, 실제 사용자 계정 승인 및 읽기 테스트를 각각 기록한다. 미등록 앱 또는 승인하지 않은 계정은 완료로 보고하지 않는다.
6. 전체 타입 검사·테스트·빌드 후 별도 프로필에서 패키지 업데이트 준비/취소·교체·롤백과 기존 및 신규 저장 파일 보존을 검증한다. 운영 앱은 사용자의 업데이트 버튼을 통해 교체한다.
